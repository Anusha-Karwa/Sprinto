# Sprinto Outbound Agent

Research → qualify → find the right person → personalised email → (review) → reply handling → booked call.
Built for MESA Term 2 AI Case 2 ("Cold Outreach, at Scale").

**The graded case (Phase A):** `python run.py domains.csv` sends a personalised, named, hooked email to
`MY_EMAIL` for each qualified company, with no human decisions mid-run, and a report that defends every
decision: why this company, why this person, why this email.

---

## Outcome (written before the prompt, L1)

> After this system runs, Sprinto's Growth Lead spends **under 2 minutes per prospect** instead of 15–20,
> rewrites **fewer than 20%** of emails, and **meetings booked per week holds or rises** versus the manual baseline.

Headline metric on every report: **meetings booked**, then reply rate, then time and edit rate.
Emails sent is activity, not outcome (the Klarna lesson).

## The five pre-build decisions

| # | Decision | What we decided |
|---|---|---|
| 1 | **Outcome** | Research + draft in < 2 min per company, for the Growth Lead. Measured by time-to-draft, edit rate and meetings booked. |
| 2 | **Baseline** | 8–15 companies a week, 15–20 min each, all manual; quality drops by the end of the list (fatigue, not worse leads). |
| 3 | **Workflow change** | She moves from researcher-writer to **reviewer-approver**: drops a domain list, reviews drafts, handles escalations. The review step is designed in and never removed (McDonald's lesson). **Against automation bias** (L1's Arjun example), every run shows her a random **10% of DISQUALIFIED** companies with reasons and a "Was this really a no?" button: the false-negative check, because the system otherwise only shows her the companies it liked. |
| 4 | **Measurement (90 days, in the world)** | Primary: meetings booked vs manual baseline. Secondary: < 2 min/company · < 20% of emails rewritten · PoC accuracy ≥ 80% · false-negative rate on the 10% disqualified sample. Instrument: after each booked call she answers "Was this meeting worth 30 minutes?" (stored on `meetings.worth_30_min`). |
| 5 | **Kill criterion** | > 50% of emails rewritten, OR PoC accuracy < 60%, OR running the tool takes longer than doing it by hand → shut it down. |

## Pipeline or agent? (L6: "most problems are pipelines — build the simpler thing")

| Part | Can the full decision tree be drawn in advance? | Built as |
|---|---|---|
| Research → qualify → PoC → draft | Yes, except "which page to read next" | **Pipeline** with one **bounded agent loop** inside Qualify (model picks the next page; code enforces caps) |
| Sequence 1: send → classify reply → branch 3 ways | Yes, one flat branch, no memory | **Hand-built**, no framework |
| Sequence 2: calendar → propose → confirm/counter/silence → retry with memory → book/escalate | No: interdependent state, a loop-back branch, retries that remember | **LangGraph** state machine with Postgres checkpointing |
| Feedback loop | Yes | Plain code + Postgres |

## Tools (four-part descriptions, generated from code)

"The model never sees your function. It sees your description." Each tool lives in `agent/tools/<name>.py`
with a `DESCRIPTION` field. This section is regenerated by `python scripts/gen_readme_tools.py`.

<!-- TOOLS:START -->
#### `fetch_page(url, target_question, reason)`  · retry policy `fetch_page`
- Does: fetches ONE page from the prospect's own site (or its public job board) and returns it cleaned.
- Use when: an ICP question is still unanswered and a specific page on the site likely answers it (e.g. /careers for stage, /security or /trust for certification, /pricing for enterprise signals).
- Do not use: for pages already fetched, login/sign-up pages, other companies' sites, LinkedIn, news sites, PDFs, or once the fetch budget is spent.
- Returns: {status: ok | blocked | not_found | robots_disallowed | empty, url, clean_text (<= 2,000 tokens), signals}.

#### `find_poc(domain)`  · retry policy `find_poc`
- Does: looks up named people and work emails at a company via Hunter.io Domain Search (or the manual Apollo file).
- Use when: a company has been QUALIFIED or QUALIFIED_FLAGGED and has no PoC yet.
- Do not use: for disqualified companies, twice for the same domain (25 credits/month), or to guess emails.
- Returns: a list of {first_name, last_name, position, seniority, department, confidence, email, source} or no_results / no_credits.

#### `send_email(kind, subject, body, thread_id)`  · retry policy `send_email.cold`
- Does: sends one email from the bot account to MY_EMAIL (the prospect stand-in), in a thread if thread_id is given.
- Use when: a cold email has been approved (kind=cold), or a confirmation must go out after a booking succeeded (kind=confirmation).
- Do not use: to propose meeting times (use propose_time), to email anyone other than MY_EMAIL, or to confirm a meeting before book_meeting has succeeded.
- Returns: {status: sent | failed, message_id, thread_id, error_class}.

#### `check_calendar(window_start, window_end, specific_times)`  · retry policy `check_calendar`
- Does: reads the Growth Lead's Google Calendar free/busy. If specific_times are given, returns free or busy for each; otherwise returns free 30-minute slots in the window (working hours, buffers, minimum notice, excluding held and rejected slots).
- Use when: Sequence 2 starts, or the prospect proposes, confirms or counters a time.
- Do not use: to list existing meetings, for dates more than 30 days out (not bookable yet), or before the prospect has said they're interested.
- Returns: {status: ok | no_calendar_access, free_slots: [...], checks: [{time, free | busy}]}.

#### `propose_time(slots)`  · retry policy `propose_time`
- Does: emails the prospect, in the existing thread, 2-3 specific meeting times (shown in their time zone and IST), and holds those slots.
- Use when: check_calendar has just returned free slots and no proposed time was free.
- Do not use: before check_calendar has run this round, to repeat times the prospect already rejected, or when reply_round has reached the cap.
- Returns: {status: sent | failed, times_proposed, message_id}.

#### `book_meeting(start_time)`  · retry policy `book_meeting`
- Does: re-checks the slot, then creates a 30-minute Google Calendar event with a Meet link, invites MY_EMAIL, and puts the prep card in the description.
- Use when: the prospect confirmed one of the proposed times, or proposed a time that check_calendar says is free.
- Do not use: without an explicit confirmation or a free prospect-proposed time, on a guessed time zone, or for anyone other than MY_EMAIL.
- Returns: {status: booked | slot_taken | failed, event_id, meet_link, start, end, error_class}.

#### `update_crm(stage, reason)`  · retry policy `update_crm`
- Does: writes the prospect's current stage and the reason to the CRM (Postgres, or HubSpot if configured).
- Use when: any stage changes, and always at every end state (booked, not interested, no reply, escalated, unsubscribed).
- Do not use: to store email bodies or as a log of reasoning (that's the events table).
- Returns: {status: logged | failed, crm_id}.

#### `escalate(reason)`  · retry policy `escalate`
- Does: hands the conversation to the Growth Lead with a summary (thread, classification + quote, what was tried, suggested next step) and pauses the agent.
- Use when: a reply is unclear, a question, a referral, or low confidence; a time is ambiguous; the retry cap is hit; there's been no reply for 48 h in Sequence 2; or a tool failed in a way the retry table says to escalate.
- Do not use: for clear "not interested" replies (end + log instead).
- Returns: {status: escalated, escalation_id}.

## Retry table (decided before the build, `config/retry_table.yaml`)

| Tool | Transient (timeout/429/5xx) | Permanent | Downstream | Policy |
|---|---|---|---|---|
| `fetch_page` | retry ×2 | blocked/captcha/login/robots/404 → skip | none | retry then skip; **homepage** blocked → company FAILED |
| `find_poc` | retry ×2 | no credits / no results | human can supply (Apollo) | retry then `needs_manual_poc` |
| `send_email` (cold) | retry ×3 | invalid auth / bad recipient | none | retry then skip prospect, log |
| `send_email` (confirmation) | retry ×3 | — | meeting already booked | retry then escalate |
| `check_calendar` | retry ×3 | no calendar access | no substitute | retry ×3 then escalate |
| `propose_time` | retry ×3 | bounce | no substitute | retry then escalate; bounce → abort + escalate |
| `book_meeting` | retry ×3 (re-check first) | invite bounce / auth | no substitute | retry then escalate; permanent → abort + escalate |
| `update_crm` | retry ×2 | API down / schema | human can log | escalate; **never blocks the run** |
| LLM calls | retry ×3 | invalid JSON twice | structure: none · draft: human | structure → FAILED; draft → `needs_human_draft` |

**Iteration caps:** qualify loop ≤ 4 fetches after the homepage · Sequence 2 `reply_round` ≤ 2 · ≤ 1 LLM redraft · tool retries per table.
One `run_tool()` wrapper (`agent/tools/runner.py`) applies the table; every cell is unit-tested (`tests/test_retry_table.py`).

## Model choices (checked against Google's docs on 2026-11-15)

- `GEMINI_MODEL=gemini-3.5-flash-lite`: Google's recommended cost-effective model for new projects ($0.30 in / $2.50 out per 1M tokens). `gemini-2.5-flash` is deprecated.
- `EMBED_MODEL=gemini-embedding-2` at `EMBED_DIM=768` (a recommended size; auto-renormalised).
- All calls: temperature 0, JSON schema enforced, validated by pydantic, thinking at the minimal level.

## Layout

```

agent/           config, models, db, llm, guards, tools/ (Tool class, run_tool, 8 tools)
pipeline/        scraper/ (fetch, parse, extract, clean, store) · structure · qualify · contacts · personalise
outreach/        Sequence 1 worker, Sequence 2 LangGraph
app/             Streamlit (review queue, pipeline, inspectors, health)
db/migrations/   numbered SQL migrations
eval/            prospect + reviewer simulations
tests/           unit tests (no real Google/Hunter/Gemini calls)
```
